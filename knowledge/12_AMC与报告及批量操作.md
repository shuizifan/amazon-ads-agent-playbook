# AMC、广告报告与批量执行

先按问题选工具。日常花费异常用标准广告报告，跨广告的去重触达、购买路径、频次和自定义人群用 AMC，形成明确行动后才用批量表格。以下为 2026 年 7 月资料，实例可用信号、受众门槛、费用、资格、字段、数据窗口、模板和广告格式须核对站点及账户当期设置。

## AMC 研究如何落到行动

**先定义问题。** 写明业务目标、研究人群、纳入哪些广告与商品、转化事件、观察区间、回溯期和比较组。选模板或无代码工具可以快速开始，复杂定义用 SQL；广告智能体生成的查询要复核表字段、去重、连接基数、事件先后、时区与窗口。图上的最长 25 个月仅涉及符合条件的广告流量信号，逐表核实可用历史。核心访问、可选付费信号、合作方服务和开发维护分别核成本。缺入口先查市场、账户资格、管理员权限、广告主及实例关联。【06 册 P107–122、P137–152】

| 研究问题 | 输入、分析和动作 |
|---|---|
| 哪些广告先触达、哪些广告收口？ | 对同类商品按时间排序曝光、点击和目标购买，区分首次/末次与中间触点；比较路径人数、购买率、新客率、耗时和成本。用结果假设预算及承接改法，另做匹配对照或实验验证净增量 |
| 组合放量是否在反复找同一批人？ | 拆 A 独有、B 独有、交集及总去重触达，比较各组购买率、商品、时期和人群构成。若重叠增加而新增触达放缓，试调整覆盖、排除、人群或预算后重新查询 |
| 频次到哪里开始浪费？ | 按频次分组，例如 1、2–3、4–6、7+ 次，按商品阶段分别比较购买率、新客、成本。看高频区间多付的成本是否换来增量；已显现高意向的人也可能天然曝光更多，不能把相关性当最佳频控值 |
| 高客单为何迟迟不见转化？ | 分别从首次曝光和首次点击起算购买时间分布，区分不同商品、价格及新老客。给高考虑商品足够窗口，再调整提醒节奏和效果观察期 |
| 应向谁交叉销售、补货或再营销？ | 看过未买需定义“看过”的事件、购买排除、窗口和更新频率；买 A 未买 B 另核兼容、相关性、购买周期、库存和毛利。耗材用真实复购间隔分组，拉新排除近期购买者，将高频未购者单独评估。规则人群与相似拓展分开验证 |

来源：06 册 P109–115、P121–131、P140–148、P152–161。

AMC 输出汇总结果。空值、被隐藏的分组或无法激活可能来自隐私阈值；扩大观察期、合并业务上可解释的分组，再校验覆盖，不能将缺数作零或反推个体。合规的第一方 CRM、订阅、线下分组等需有相应权利、合法处理和清晰字段定义，通过实例允许的 Data Manager 或集成接入；先写清“高价值”按毛利、复购还是销售判定。可重复的成熟流程再用报告、受众管理、信号接入 API 自动化。日常看标准报告，等数据稳定后再跑 AMC，新品先留够样本，成长看协同和重叠，成熟看长期响应与复购。【06 册 P114–120、P127–140、P148–161】

## 哪份搜索广告报告能回答当前问题

| 问题 | 先查及交叉验证 |
|---|---|
| 哪个活动拖累整体、有没有预算约束？ | 活动报告定位异常，再看按日数据与预算报告的预算、实花、用尽时间；盈利且反复用尽才有扩大空间，花不完先查流量、资格和竞价 |
| 广告设置的目标和实际引来的流量分别是什么？ | 投放报告看关键词、自动匹配分组、ASIN 和类目；搜索词报告看实际查询或关联 ASIN。高相关且稳定出单可独立精准测，明确不相关可否，样本少可继续看；否 ASIN 用商品否定实体 |
| 哪个 ASIN 花了钱，买家最后买谁？ | 推广商品报告看被展示品；已购买商品报告看最终购买品，拆同品牌带动、替代变体与互补品。先核利润和库存，再拆分抢预算的弱 ASIN |
| 顶部值得加价吗，核心词还有空间吗？ | 广告位报告分顶部、其余搜索和商品页，同时看 CPC、CVR、每单广告成本。搜索词展示份额和排名只说明广告竞争位置，高转化低份额再查可得机会和增量利润 |
| 为什么同一周期数对不上？ | 核产品、范围、汇总/按日、时区币种、归因窗、生成/回补时间、过滤、报告维度与点击收录条件。无效流量过滤可能造成更新差异。检查条件相同后再判断差异，跨报告的同一订单不能相加 |

来源：06 册 P162–187。

按日表现用来定位 CPM/CPC 或转化变化的开始日期，叠加促销、价格、库存、预算用尽事件。聚合到周/月或跨活动时重算 CTR＝总点击÷总展示，CVR＝总归因订单÷总点击，CPC＝总花费÷总点击，ACOS＝总广告花费÷总广告归因销售额，ROAS＝总广告归因销售额÷总广告花费。为零的分母标记不可计算。广告组、创意、视频、品类基准等补充报告按账户可见字段使用。留存有明确对象、原因、动作和验证期的调整清单，支持下次重下同口径报表。【06 册 P175–187】

## 如何把判断写成可核对的批量动作

1. **选对文件。** 从零创建用当期空模板；更新既有对象时下载含真实 ID 的最新自定义表，核广告产品、零展示实体、状态及广告位数据。自定义下载日期和只读搜索词附表的时间可不同；资料示例分别为通常最长 60 天及固定 7 天，以当期页面为准。保留源文件，编辑副本，不改页签/列名。只读搜索词页辅助定位 Campaign/Ad Group/投放 ID，回活动页填写修改，只粘贴数值。【06 册 P188–195、P210–212】
2. **明确每行作用。** Product 定广告产品，Entity 定实体，Operation 定 Create、Update 或 Archive。只给意图执行的行填写 Operation。启用/暂停使用 Update 配 enabled/paused；Archive 为永久归档，按模板核 State。一个实体一行，Campaign→Ad Group→Product Ad、Keyword 或 Product Targeting。否词/否商品挂可用的正确层级，Bidding Adjustment 属 Campaign。【06 册 P193–200】
3. **创建和复制。** 新建活动与广告组用文件内唯一临时文本 ID，父子引用须完全一致；成功后重下载，更新须换系统 ID。手动 SP 需要活动、组、商品和相应目标，卖家/供应商按模板填 SKU 或 ASIN；否定和位置调整按策略添加。自动 SP 设 AUTO，细分 close-match、loose-match、substitutes、complements。复制成熟结构时换新临时父 ID，并按要求清已有子 ID，再改商品、竞价和预算。【06 册 P196–203、P209–211】
4. **更新。** 真实 Campaign/Ad Group/Ad/Keyword/Targeting ID 仅用于定位。按模板核允许变更的名称、竞价、日预算、状态、结束日及位置百分比；系统 ID、开始日、投放类型、词和匹配、SKU/ASIN、目标表达式通常应通过新实体实现。End Date 在部分 Update 场景留空会清掉结束日，副本保留原值或明确新日期。区分广告组默认 bid、目标 bid、活动策略和广告位加价。批量调预算前排除缺货、转化走弱与原预算花不完的活动。【06 册 P198–209】
5. **执行与验证。** 先复核动作数、父子对应、归档清单、日期格式、金额及百分比；首次使用新字段或跨站点，大批量前先用小批验证（资料举 5–20 行）。上传后按成功、警告、错误记录对账。用 Original record #、Error code、Error message 定位原行；父级失败可能使子级尚未执行，先修父并核实成功行，避免重复创建。重新下载实体核对预期设置，约定观察期后用同口径报告复盘效果。【06 册 P211–223】
