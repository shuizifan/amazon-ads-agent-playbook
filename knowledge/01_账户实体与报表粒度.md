# 账户实体与报表粒度

## 看懂一个 SP 广告结构

同一广告账户和站点内，广告活动可以归入广告组合。活动下面有广告组。一个组里同时包含两类对象：负责“推广哪件商品”的商品广告，以及负责“争取哪些机会”的投放目标。实际搜索词和最终成交的商品由投放结果产生。将这些对象保存在不同字段，才能把花费归给正确的决策层。

| 对象 | 它回答什么 | 设计或诊断时保留什么 |
|---|---|---|
| 广告组合 Portfolio | 哪些活动属于同一个经营目标、产品线或负责人 | 组合 ID、归属规则和预算约束；保留未归入组合的活动 |
| 活动 Campaign | 哪项任务共享预算、竞价策略和活动设置 | 活动 ID、广告产品、任务、预算、状态、生效日期及支持的位置调整 |
| 广告组 Ad group | 哪组商品与目标一起竞争、复用默认竞价 | 广告组 ID、活动 ID、组状态和默认竞价；分别保存目标级自定义竞价 |
| 商品广告 Product ad | 哪个 SKU 或子 ASIN 在获取流量 | 商品广告 ID、SKU、推广子 ASIN、父 ASIN 和可售状态。同 ASIN 在多个活动投放时，各实体分别归属 |
| 投放目标 Target | 系统依据什么获得展示机会 | 目标 ID、关键词及匹配类型、ASIN/品类定向表达式或自动匹配组；保留正向与否定属性 |
| 实际搜索词 Customer search term | 什么查询或商品上下文触发了匹配 | 保留查询原文或 ASIN、来源目标和日期。检索时可另建归一化词形，否词决策回到原始表达 |
| 广告位 Placement | 展示出现在哪里 | 在支持该维度的报表中记录位置、窗口、加价和实际表现。位置与定向是两个维度 |
| 已购商品 Purchased product | 点击后实际买了什么 | 购买 ASIN、对应归因指标、期间及与推广商品的关系。区分商品件数、订单和件单量 |

SP 的这套层级适合理解商品广告；SB、展示及电视产品另有创意、品牌落地页、受众和触达指标。建模时以相应产品的报表字段为准。依据第 01 册第 4–29、59–89 页，第 04 册第 29–43、56–79 页，第 06 册第 175–210 页。

## 广告组合怎样对应产品、系列与职能

组合是多个活动共用的管理和观察范围。按产品或系列归集，适合直接看一条产品线的总投入；按职能归集，适合给探索、稳定成交、品牌防守等任务分别分配资源。两种方式可以并用。例如，小系列的各类活动放在“示例收纳盒系列”；活动多、职能需要独立管理时，可分为“示例收纳盒系列-需求探索”和“示例收纳盒系列-稳定成交”。品牌推广覆盖多个系列时，也可设“全品牌-品牌防守”，同时保留所覆盖的商品清单。组合的预算约束若已启用，要和下属活动各自的预算一起读。

这里有两条不同的汇总路径。**管理视图**按组合归属汇总活动，单列未归组活动。**经营视图**按推广子 ASIN 对应的父 ASIN 或系列汇总，跨组合找齐同一产品的活动。单品活动可直接归属；混投多个父体的活动，使用推广商品明细中实际可拆的花费。品牌创意共用花费且缺少可拆数据时，标为“系列共享／待分摊”。各产品已归属花费加上共享花费应能与范围内活动总额对账。购买商品报表另用于解释成交去向。活动移组时保留调整时间和原组合 ID，以区分历史归属与当前组织结构。

## 组合、活动和广告组的中文命名

| 层级 | 建议格式 | 同一套结构的示例 |
|---|---|---|
| 广告组合 | 简短品名或系列名；需要按职能归集时加“-职能” | 示例收纳盒系列；示例收纳盒系列-稳定成交 |
| 广告活动 | 简短品名-广告类型-推广方式-任务 | 示例收纳盒-商品推广-关键词精准-稳定成交 |
| 广告组 | 款型或适配子体-词群、商品群或受众主题 | 中号款-规格核心词 |

广告类型统一用“商品推广、品牌推广、展示广告”等。推广方式按实际配置选用“自动、关键词广泛、关键词词组、关键词精准、商品定向、浏览再营销”等；任务用“需求探索、稳定成交、排名测试、品牌防守、竞品拓展、复购”等。活动混合多种匹配时可用“关键词混合”，再按组或目标记录实际配置。组名有歧义时加用途或规格；跨站点合并管理时统一加“美国／加拿大”等前缀。预算、竞价、当前排名等会变的数值保存在配置记录中。旧名称可以保留，维护“站点＋实体 ID＋现名＋规范别名”映射，避免只为统一名称重建已有活动。本节属于运营命名约定。

## 哪种需求值得拆活动

| 理由 | 建议的最小拆分 | 拆完怎样验收 |
|---|---|---|
| 要独立控制预算、位置策略、重点时段或承担不同的经营任务 | 分活动。为探索、稳定成交、品牌防守或限时促销写清各自的主指标 | 新活动能拿到样本，原有有效订单没有因流量断档明显减少，总预算与利润可对账 |
| 同一任务下需区分主题、适配商品或单独管理默认竞价 | 活动内按意图分广告组，保留活动预算共享这一条件 | 同组商品可用相同查询和页面承接，报表足以判断下一步 |
| 个别词需要不同价格，其他目标仍承担同一任务 | 优先用目标级竞价。若需单独位置控制、预算保障或止损，再论证拆成活动 | 比较目标自身的点击成本和活动整体订单；不以新建活动数量评价结构 |
| 多子体价格、功能或库存差异明显 | 按购买意图、库存承接、毛利和必要的预算边界拆；保留父子映射 | 能分别看到推广子体、购买子体及父体贡献，并留足每组样本 |

连接数据和回读变更用实体 ID；活动改名后，历史记录仍归到原 ID。结构取舍参见第 07 册第 118–145 页、第 08 册第 90–102 页。

## 如何从业务问题确定取数粒度

1. **写出一行代表什么。** 例如按“站点 × 活动 ID × 日期”核花费；按“活动 ID × 广告组 ID × 目标 ID × 实际查询 × 窗口”判断搜索意图。搜索与商品页两种入口要保留原始对象类型。
2. **选一张主表。** 预算诊断用活动和预算历史，位置诊断用位置报告，找要否定的查询用搜索词报告。要解释总量时另取活动控制总计，并记录两表的范围、过滤条件、归因窗口与更新时间。
3. **限制能做的连接。** 用站点/账户和实体 ID 关联配置。若一个活动关联多个目标或子体，将活动花费直接连接到每个目标再求和，会重复计算。不同报表描述同一笔订单时按各自问题使用。需要一个报表没有提供的交叉维度时，给出可验证的更细数据需求，或用隔离投放设计后续测试。
4. **保留无法区分的部分。** 过滤后的可见行、截断的金额、数据暂缺、未归因和实际零分开标注。把“已按同范围对账”“仅部分覆盖”“无法对账”作为结论的一部分。日期、币种或站点不同的同名活动不能直接拼在一起。
